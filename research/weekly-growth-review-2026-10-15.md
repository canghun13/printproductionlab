## Technical reproduction and repair

- Target: shared Footer on `/tools/booklet-creep-calculator.html` at 900; controls: same page at 1024/768/390, Home, Guides hub and Smart Label's alternate footer template. Overflowing nodes were Footer legal-text elements, not calculator controls.
- Root cause: legacy critical inline CSS reserves 220+150+150+260 = 780 px tracks, 96 px gaps and 56 px padding, requiring 932 px. The alternate template uses 790 px tracks + 90 px gaps + 56 px padding, requiring 936 px. The existing mobile rule starts only at 768, leaving the tablet interval unable to contain four columns.
- Minimal production change: one scoped rule in `assets/css/layout-refinement.css`, only **769–935 px**, changes `.footer .footer-inner` to two `minmax(0,1fr)` columns. The important declaration overrides the existing important legacy grid tracks. No magic element margin, clipping workaround, body overflow rule or badge selector was added/changed.
- Desktop from 936 and mobile through 768 retain their established rules. Main/header/H1/control boxes match baseline at tested boundaries; footer geometry/columns match baseline at 936/1024/768/390. All HTML, calculator JS, generator, metadata, IDs, content, URLs, sitemap, robots and llms files are byte-unchanged relative to start. Owner-managed footer/badge markup and existing badge CSS are untouched.
- Focused live health: Home, target, Roll Diameter, Book Spine, Smart Label hub and Guides hub HTTPS 200, correct self-canonical, no noindex; robots/sitemap/llms 200; Googlebot target 200; HTTP and www target normalize to HTTPS apex.
